## Why the runs failed, grouped

- **The calls parse and run.**
  - None of the 700 responses carries a tool call as text; every call is a structured `tool_calls` entry.
  - goinfer's "tool calls are not constrained for these tools" line appears zero times in both serve logs.
  - Tool results come back to the model as the tools produced them. Task 2's `go test` output reached it twelve
    times.
  - The first run's defect is gone. In it, two runs had ended on a call emitted as text, and a third on text that
    looked like one.
- **Ended early, without changing code: 13 runs.** Each ended on the model's own `stop` (or, task 9 A0, the cap)
  with an empty diff. It answered in prose instead of editing:

  - a summary or explanation: tasks 3 A0k, 5, 7, 9 A0k, 10;

  Task 9 A0 is a loop: after opencode compacted the conversation, the model searched for an `aikit` directory inside
  the aikit repository until the cap.
- **Changed code, wrongly: 5 runs.**
  - deleted most of the file it should have extended: task 1 A0k;
  - edited the wrong package: task 3 A0;
  - overwrote an unrelated README: task 4 A0k;
  - small edits that do not add what the oracle's test calls: task 11 (both arms).
- **The right fix, a broken build, then a loop: 2 runs** (task 2, both arms). Each made the correct one-line change
  (`strings.ToLower(ext)`) without importing `strings`. Then it ran `go test` repeatedly, read
  `undefined: strings` each time, and never added the import, until the cap.

## Is the pass check right?

As far as the saved records can show, yes:

- **Every empty-diff run reproduces the miner's parent result.** Each of the 13 runs with no diff is the task's base
  commit, and each got exactly the status the miner recorded at the parent: `build-fail` where the parent was
  `build-fail` (tasks 1, 3, 6, 9), and `fail` where it was `fail` (tasks 4, 5, 7, 10). For goinfer and ken the oracle
  compiled and ran the test on nobara.
- **Task 2's `build-fail` is a real compile error,** the same `undefined: strings` the model saw.

Three gaps remain:

- **No saved record shows the oracle passing on nobara.** The miner verified each task's pass at its commit with the
  same command, but no positive control ran in the pilot's environment. For aikit (tasks 1, 3 and 9) the oracle has
  only ever reported `build-fail` there, so a broken aikit environment could not be told apart from code that does
  not yet exist.
- **`build-fail` is a catch-all.** `mine.RunTests` gives it to any oracle test that never reports, whether from a
  compile error, a module fetch, a timeout or `go` failing to start. `pilot.Oracle` drops its error and saves no output.
  The records can only show that a test did not report, not why.
- **`results.jsonl`'s tool-call count undercounts.** Its `events.tool_calls`, from opencode's event stream, recorded 0
  calls for task 2 A0, where the raw bodies show 82. The table above uses the raw bodies.
