## Why

- **Qwen2.5-Coder-7B-Instruct does not call tools once it is offered several.**
  - In smoke it made no tool call on any of the 20 tasks, in either run. Its two passes are the two tasks where
    calling no tool is the right answer.
  - goinfer's `check` shows the boundary:
    - with one tool it calls it (`get_weather`, 2 turns);
    - with the 12-tool schema it answers without calling ("too small for tool use, or its template has no tool
      section"), on both `/v1/chat/completions` and `/v1/messages`.
  - Its template is not the cause. Its GGUF carries the same tool section (`{%- if tools %}`, `<tool_call>`) as the
    incumbent's, and the incumbent calls the tool among 12 and scores 18/20.
  - Its speed is the incumbent's, 85.6 tok/s against 85.7. Coder tuning cost it tool use, not speed.
- **Seed-Coder-8B-Instruct has no tool-calling template.**
  - Its GGUF holds no tool section, and goinfer answers every request that carries tools with `400 this model has no
    tool-calling template`.
  - So smoke scored 0 in 11 ms and every TTFT request failed, which made the arm void.
  - It is the same failure that retired phi3-mini-4k (amendment 5). Retiring it likewise is the owner's call.

## Decode audit (2026-10-18)

Until tack `38137f5` (see `e1-calibration-preregistration-2026-10-18.md` §8), E0's decode probe
(`internal/eval/runner.go:decodeOnce`) worked this way:

- it asked for no thinking;
- it divided every output token the server counted by the time between the first and last streamed delta.

goinfer drops the reasoning of a request that did not ask for thinking, so tokens of a reasoning channel were counted
but not timed. The raw stream and goinfer's request log for these runs were not kept: E0's servers logged to a
temporary directory. So no figure can be recomputed. Each is judged by whether its model's template has such a
channel:

| figure | model | reasoning channel goinfer could drop | status |
|---|---|---|---|
| 68.3 tok/s | gemma-4 E4B | yes: gemma-4's thinking is "unmanaged", and its template has a channel form | **unverified** |
| 85.6 tok/s | gemma-4 E2B | yes, as E4B | **unverified** |
| 85.7 tok/s | Qwen2.5-7B-Instruct (chatml) | no | stands: every generated token streamed as text |
| 85.6 tok/s | Qwen2.5-Coder-7B (chatml) | no | stands |
| 80.6 tok/s | Seed-Coder-8B (no recognised template, raw completion) | no | stands |
| 29.9, 93.6, 206, 17.8 tok/s | Qwen2.5-7B, -Coder-1.5B, -Coder-0.5B on the Mac (`e0-mac-2026-10-16.md`), chatml | no | stand |

The fixed probe asks for thinking, times thinking and text alike, and refuses a reply that counted more tokens than it
streamed characters. Re-measuring the two gemma-4 figures on it is a new measurement, not a recompute, and waits for
the owner.
